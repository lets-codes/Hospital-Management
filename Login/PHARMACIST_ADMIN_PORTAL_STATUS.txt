3. API ENDPOINTS (NEW)
================================================================================

PHARMACIST ENDPOINTS:
  GET  /api/pharmacist/inventory
       - Retrieves all medicines with pending request counts
       - Parameters: actor_id (pharmacist ID)
       - Returns: medicines array with stock levels

  POST /api/restock-request
       - Submit restock request for medicine
       - Body: medicine_id, medicine_name, requested_by, requested_quantity, reason
       - Returns: request ID and confirmation

  GET  /api/health
       - Server health check

ADMIN ENDPOINTS:
  GET  /api/admin/restock-requests
       - List all restock requests
       - Parameters: actor_id (admin ID), status (pending/approved/rejected/all)
       - Returns: filtered request list with details

  PUT  /api/admin/restock-request/{id}/approve
       - Approve restock request and update inventory
       - Body: actor_id, admin_notes (optional)
       - Returns: confirmation with updated stock levels

  PUT  /api/admin/restock-request/{id}/reject
       - Reject restock request with explanation
       - Body: actor_id, rejection_reason
       - Returns: confirmation

GENERAL ENDPOINTS:
  POST /api/medicines
       - Add new medicine to inventory
       - Body: name, sku, manufacturer, quantity, unit_price, expiry_date, actor_id
       - Returns: medicine ID

  GET  /api/medicines
       - List all medicines

4. DATABASE SCHEMA CHANGES
================================================================================

CREATED TABLE: restock_requests
  - id (INT, Primary Key, Auto-increment)
  - medicine_id (INT, Foreign Key to medicines.id)
  - medicine_name (VARCHAR 255)
  - requested_by (INT, Foreign Key to login.id - pharmacist)
  - pharmacist_name (VARCHAR 255)
  - requested_quantity (INT)
  - reason (TEXT)
  - status (ENUM: pending, approved, rejected)
  - admin_notes (TEXT)
  - approved_by (INT, Foreign Key to login.id - admin, nullable)
  - requested_at (TIMESTAMP)
  - approved_at (TIMESTAMP, nullable)

MODIFIED TABLE: login
  - Extended role ENUM from ('patient','doctor','admin') 
                       to ('patient','doctor','admin','pharmacist')
  - Impact: All 4 roles now fully supported with database constraints
