TWO-WAY COMMUNICATION SYSTEM - FULLY ESTABLISHED
================================================================================

The portals now communicate bidirectionally:

PHARMACIST → ADMIN (Request Flow):
1. Pharmacist views medicines in /pharmacist_portal.html
2. Pharmacist identifies low-stock items (red badge when ≤10 units)
3. Pharmacist clicks "Request Restock" button
4. Pharmacist enters quantity and reason
5. System sends POST to /api/restock-request with:
   - medicine_id, medicine_name, requested_quantity, reason
   - actor_id (pharmacist's user ID), role validation
6. Request stored in restock_requests table with status='pending'
7. Admin immediately sees new request in /admin_portal.html

ADMIN → PHARMACIST (Approval/Rejection Flow):
1. Admin views restock requests in /admin_portal.html
2. Admin filters by status (Pending, Approved, Rejected)
3. Admin clicks "Approve & Add to Stock" button
4. System sends PUT to /api/admin/restock-request/{id}/approve with:
   - actor_id, admin_notes (optional)
5. Backend automatically:
   - Updates restock_requests status to 'approved'
   - Adds requested_quantity to medicine stock
   - Records approval timestamp and admin ID
   - Returns updated quantities in response
6. Pharmacist sees updated inventory and can view request status in:
   - /api/pharmacist/inventory (stock quantity increased)
   - /api/pharmacist/restock-requests (status changed to APPROVED)

ALTERNATIVE: Admin Rejects Request:
1. Admin clicks "Reject" button on pending request
2. System sends PUT to /api/admin/restock-request/{id}/reject with:
   - actor_id, rejection_reason
3. Backend:
   - Updates status to 'rejected'
   - Stores rejection reason in admin_notes
   - Records rejection timestamp
4. Pharmacist sees:
   - Request status changed to REJECTED
   - Admin's rejection reason with explanation
   - Can resubmit request if needed (by requesting again)
